# Troubleshooting

Use the returned status/code and server configuration rather than bypassing validation. Backend variables are read from the process environment; the root `.env` is not automatically loaded.

| Symptom | Likely cause / what to check | Expected behavior and safe fix |
| --- | --- | --- |
| Production model files missing | Check `CROP_HEALTH_MODEL_CHECKPOINT`, `CROP_HEALTH_CLASS_MAPPING`, and the configured production files. | `/health/ready` reports `model: unavailable`; `POST /predict` returns `503 model_unavailable`. Provide a separately trained, reviewed production checkpoint and matching mapping when ready. Do not point to the smoke folder. |
| `model_unavailable` from prediction | Production artifact missing, smoke path rejected, incompatible mapping, or load/inference failure. | The API does not invent output or fall back to smoke. Check paths, class IDs, permissions, and error logs; use the model workflow to prepare a real artifact. |
| `database_unavailable` or history returns no service | `DATABASE_URL` missing or incorrect, database not reachable, or migrations not applied. | Check the process environment and database connectivity; apply `python -m alembic -c alembic.ini upgrade head` before database-backed requests. `/health/ready` checks connectivity. SQLite is for local work/tests; use PostgreSQL for deployment. |
| Alembic reports no URL / connection error | The Alembic process does not inherit `DATABASE_URL`, driver/URL is wrong, or target DB is unavailable. | Set `DATABASE_URL` in the same shell/process, verify the PostgreSQL `psycopg` URL or local SQLite URL, and run `alembic current`/`upgrade head`. The application does not migrate on startup. |
| Browser CORS error | Browser origin does not exactly match `CORS_ALLOWED_ORIGINS`, or browser is calling a different API origin. | Include the exact scheme/host/port of the frontend in the backend environment and restart it. Use comma-separated explicit origins; wildcard is rejected. The Vite proxy avoids direct cross-origin calls during local development. |
| Requests go to the wrong backend | `VITE_API_BASE_URL` is wrong or was changed after the last frontend build. | Check the browser network URL. Set the backend origin (no `/predict` suffix) and rebuild/restart Vite. Production Vite variables are embedded at build time. |
| Backend/frontend port conflict or connection refused | Backend not running, API bind host/port differs, or Vite proxy target is not the local API. | Check `API_HOST`, `API_PORT`, launcher output, and the Vite proxy target (`127.0.0.1:8000` by default). Keep both services running in separate terminals. |
| Weather shown unavailable | Place could not be geocoded, provider timed out/failed, payload was invalid, or network access is unavailable. | This is a supported safe state. Check location spelling and `WEATHER_*` URLs/timeout. Disease-based recommendations remain; weather context is not fabricated. Tests use mocked provider calls. |
| Invalid image / corrupt upload | File is empty, damaged, or cannot be decoded. | Select a valid JPEG, PNG, or WEBP and wait for validation. Do not rename corrupt bytes to bypass validation. |
| Unsupported image type / content mismatch | Extension, declared MIME type, and decoded content disagree, or format is unsupported. | Export the image as JPEG, PNG, or WEBP and upload with matching type/extension. Backend validation remains authoritative. |
| Oversized image | File exceeds configured byte limit or decoded dimension/pixel limit. | Use a smaller legitimate image within `configs/prediction_config.yaml` bounds. Do not disable limits. |
| Invalid lesion mask | Mask is not PNG, cannot be decoded, exceeds limits, or does not align with the oriented source image. | Use a valid aligned PNG mask. The mask is optional; remove it to request classification without severity. Do not rescale independently unless it remains aligned. |
| Severity says `not_requested` | No lesion mask was supplied. | This is expected: the current estimator requires an aligned PNG lesion mask. It does not mean the plant has no disease. |
| Grad-CAM unavailable | Explainability generation failed or could not be matched to the predicted class. | The prediction workflow treats Grad-CAM failure as nonfatal and reports `explainability.status: unavailable`. Check model artifact compatibility/logs; do not infer disease from a missing map. |
| History is empty | No persisted predictions exist, the selected class filter has no matches, or the configured DB has no records. | Clear the filter or verify the configured database. Empty history is an honest empty state; the UI does not generate sample rows. |
| Frontend tests/build fail | Dependencies are absent/incompatible, wrong working directory, or build-time environment/config issue. | From `frontend/`, run `npm.cmd ci`, then `npm.cmd test -- --run` or `npm.cmd run build`; inspect the first reported error. Do not suppress a failing test or remove validation. |
| Python import/dependency failure | Wrong Python environment/version or project requirements not installed. | Activate the supported Python 3.11–3.12 environment, run `python -m pip install -e .`, and execute project commands from the repository root. Verify with `python -c "import sys; print(sys.executable, sys.version)"`. |

For startup and command details, see [getting started](getting_started.md). For endpoint codes, see [API usage](prediction_api.md); for deployment checks, see [deployment](deployment.md).
